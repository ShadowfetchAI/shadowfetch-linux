# Shadowfetch Linux-First Operating Plan

**Goal:** make Shadowfetch Linux the public front door, with the App Shelf as supporting proof that Shadowfetch ships useful tools.

**Operating rule:** every task must move one of four lanes: Trust, Proof, Distribution, or Feedback.

## Owners

### Brandy — strategy and final calls
- Publish founder note: “Why Shadowfetch Is Building a Linux Workstation Now.”
- Approve the public brand line: “Shadowfetch builds a private, AI-ready Linux workstation for creators, backed by a deep shelf of focused iPhone and iPad tools.”
- Keep top-level copy Linux-first; use App Shelf only as support.
- Ship a 30-day operating memo.

### Jess — execution system
- Maintain launch board across Trust Infrastructure, Reviewer Outreach, Directory Listings, Content, Community Feedback, Release Engineering, Done.
- Own the reviewer-kit checklist.
- Run daily 15-minute status checks: shipped, blocked, proof created, public artifact changed.
- Enforce the no-loose-claims rule: verified, sourced, roadmap-labeled, or removed.

### Elaine — Linux trust
- Keep `/linux/verify`, `/linux/known-issues`, `/linux/hardware`, `/linux/security`, `/linux/roadmap`, and `/linux/faq` current.
- Collect hardware reports and convert them into tested-machine notes.
- Define v1.2.9 release criteria from actual user friction.
- Keep Debian relationship language accurate: independent derivative, no endorsement claim.

### Sheena — App Shelf
- Curate 112 public iOS apps into clear categories.
- Pick 12 featured App Shelf apps with clean one-line blurbs.
- Verify App Store links, screenshots, privacy-policy links, and names.
- Keep the Shelf framed as proof of shipping, not the main product.

### Emily — metrics and reality check
- Track ISO page visits, ISO downloads, verification visits, known-issues visits, App Shelf outbound clicks, blog reads, social visits, and directory referrals.
- Publish weekly metric report.
- Maintain cost/risk table: Cloudflare/R2, build machine, signing/release maintenance, support burden, legal/privacy claim risk.
- Maintain “stop doing” list for work that does not move trust, proof, distribution, or feedback.

### Summer — social
- Draft and schedule 10 concrete launch posts.
- Produce five 30–60 second demo scripts: boot, local AI, creative tools, verification, App Shelf proof.
- Maintain reply playbook for “just Debian?”, “why another distro?”, privacy, NVIDIA, Secure Boot, and target users.
- No guru voice. Proof over hype.

### Kaitlan — narrative and outreach
- Maintain one-page press brief.
- Maintain reviewer pitch.
- Build first 25 outreach targets.
- Write the “known issues are good” story: serious projects publish rough edges.

## 7-day cadence

### Day 1–2: Trust foundation
- Elaine updates trust pages.
- Jess updates launch board and reviewer kit.
- Emily confirms metric events or manual counters.

### Day 3: Narrative package
- Brandy founder note.
- Kaitlan press brief.
- Summer launch posts.
- Sheena App Shelf feature picks.

### Day 4: Reviewer kit
- ISO links, screenshots, verification guide, known issues, hardware notes, pitch copy.

### Day 5: Public push
- Founder note, launch thread, directory submissions, reviewer outreach.

### Day 6–7: Feedback loop
- Track reactions, collect bugs, update known issues, prioritize v1.2.9, publish “what we learned.”
